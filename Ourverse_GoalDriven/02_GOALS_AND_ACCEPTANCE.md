# OURVERSE — Goal-Driven 目标分解、阶段闸门与验收标准

执行说明：一次只将**一个阶段**作为运行中的 Goal；总目标保存在 `01_PRD.md` 作为项目北极星。前一阶段没有独立证据不得自动宣称后续完成。

## 全局 Goal

> 在当前工作区构建可独立运行的 OURVERSE 双人私人数字记忆 Web 应用：具备真实的双人隐私模型、回忆记录和媒体管理、星空时间线、纪念日/时间胶囊、可断网打开的数字博物馆导出，以及可关闭且有来源引用的记忆检索助手。提供完整源码、数据库迁移、自动化测试、可复现运行说明和验收报告。按 S0→S5 阶段推进；以测试和可操作演示为通过依据，不以生成文件数量作为完成依据。

## 通用开发循环与停止规则

1. 先检查代码仓库、分支、已有内容和权限，不覆盖现有有用代码；若为空则初始化。创建 `docs/PROGRESS.md`。
2. 将当前阶段拆为 `plan → implement → test → review → fix`，失败后诊断具体根因，不通过删除测试/屏蔽错误来制造成功。
3. 每轮维护 `docs/PROGRESS.md`：阶段 / 上一次实际执行命令 / 结果 / 当前 blocker / 下一步。
4. 只有证据满足当前阶段的每项标准才能标记 `PASS`，否则 `FAIL` 或 `BLOCKED`。
5. 外部账号、服务密钥、邮箱验证、用户真实素材、付费操作或公网部署均需用户显式参与。无法执行时停在 `BLOCKED_EXTERNAL`，交付本地可复现的剩余能力。
6. 默认最少权限；禁止 `git push`、公开部署、上传真实素材或购买服务，除非用户后续明确授权。
7. 保持每阶段可运行，提交小的可回滚 git commits（仅本地）；禁止借助虚假的 mock 成功替代真实后端验收。
8. 如果连续三次改动没有改善同一失败，先写 root-cause 分析并调整路线，而不是无穷重试。
9. 主 Agent 对交付和验收负责；子 Agent 可并行做互不冲突的工作（UI、数据库、安全审计、测试），但禁止多个代理同时覆盖同一文件。子 Agent 完成后由主 Agent 复验。
10. 对外部依赖做明确隔离，若无权限/服务则用 demo mode 继续，但真实后端的验收项必须保持 `BLOCKED`。

## S0 — 仓库审计、骨架和设计契约

交付：TypeScript strict + Vite React 初始化，依赖锁定、路由外壳、设计 token、演示数据模型、`.env.example`、基本 CI/verify 命令、`docs/architecture.md`。

验收：
- `npm ci`（若新项目第一次锁定则 `npm install` 后检验）成功。
- `npm run typecheck && npm run lint && npm run test && npm run build` 返回零退出码。
- 本地开发服务可打开 `/login`、`/app`、`/app/timeline`、`/app/stars`、`/app/settings`；空路由有 404 和合理跳转。
- 页面在 375px/1440px 下没有关键 UI 横向溢出（Playwright 截图存 `artifacts/screenshots/`）。
- 无生产密钥、无编造的真实账号/记忆内容；demo 画面明确标注 DEMO。

## S1 — 双人身份、隐私与记忆 CRUD

交付：Supabase migration、Auth、空间与成员邀请机制、RLS、私有存储与签名访问、回忆列表与 CRUD、搜索与过滤、附件管理。无外部凭据时落地 demo repository 和模拟用户流以持续开发。

验收：
- 真实后端集成环境可完成 A 创建空间 → B 接受一次性有效邀请 → A/B 登录 → 各自写入和查看 shared 记录。
- A 的 private 记录对 B、第三个测试账号与匿名者不可访问：数据库 SELECT / Storage / 导出 / 搜索接口均有负向测试。
- B 不能编辑或删除 A 的记录；邀请过期、重复使用和第 3 人加入均被拒绝。
- 20 条 CRUD/权限综合测试（至少 8 条为失败/越权用例），无跳过的关键权限测试。
- 5MB 图片（测试素材）上传、显示、删除链路通过；非法 MIME 或超限文件有错误提示。
- `supabase test db` 或同等真实数据库 RLS 验证记录在报告中；无 Supabase 时写 `BLOCKED_EXTERNAL`，不能将 demo 当作 RLS PASS。

## S2 — 星空、时间线、纪念日、时间胶囊

交付：响应式记忆时间线、星空视图、可点击星点、纪念日自定义、时间胶囊创建/锁定/解锁；动效降级。

验收：
- 12 条虚构样本按日期正确排序；星空里每个可见星点都能定位到真实存在的一条记忆。
- 手机与桌面导航均可完成：首页 → 星空 → 查看记录 → 时间线。
- 修改或删除记录后时间线和星空一致，不存在虚假的静态星星详情。
- 时间胶囊到期前返回正文的服务端请求被拒绝；到期后有权限成员可访问；将本机时间调快不能提前解锁。
- `prefers-reduced-motion` 时不存在持续闪烁动效；可使用纯文本时间线完成相同核心任务。
- 至少 5 条 Playwright E2E 覆盖以上路径，截取移动端与桌面截图。

## S3 — 真正离线的数字博物馆

交付：可选择范围的 ZIP 导出、完整资源目录、相对路径浏览入口、Markdown/JSON 可迁移副本、SHA256SUMS、恢复指南。

验收：
- 在演示数据中生成一份包含 12 条记录、>=6 件媒体的离线 ZIP。
- 全新目录解压后，在**完全断网**环境，双击 `index.html` 能查看文字、图片、导航、时间线（不依赖本地 server）。
- 离线包不包含 `http(s)` 远程资源、任何 API key/token/签名 URL；静态检查与运行检查通过。
- 全部导出文件校验哈希一致；任意篡改一个文件后校验脚本能报错。
- 导出权限单测覆盖 A 无法导出 B 的 private，除非 B 自己发起独立导出；shared 与 private 的选择正确。
- 至少手动验证一次图片加载、音视频播放（受浏览器编解码限制时记录）；不能运行 GUI 时报告 BLOCKED，保留可执行检查指令。

## S4 — 记忆检索助手（先检索后接模型）

交付：关键词/日期搜索、来源证据卡、可选模型 adapter、用户明确启用开关、隐私过滤、失败安全降级。

验收：
- 测试集中 20 道问题，包含 8 道可答题、6 道无证据题、6 道权限隔离题。可答题要求返回可定位的 source ID，无证据题不能编造具体事实，隔离题不能泄漏私有内容。
- 使用 fake model 测试：输入错误或无关答案时不得保存到真实记忆；模型接口超时返回可恢复错误。
- 禁用模型 API 的条件下，搜索页面正常可用（明确提示“仅检索模式”）。
- 服务端保管密钥，敏感正文仅在用户授权开启 AI 后发送；异常日志不写敏感明文。
- 若未配置真实提供商则模型质量测试记为 BLOCKED，不影响纯检索 PASS。

## S5 — 发布候选与交付（必须由主 Agent 复核）

交付：稳定源码、文档、验证脚本、完整演示录屏建议/截图、迁移与回滚指南、验收证据表。

验收：
- `npm run verify` 执行 typecheck/lint/unit/build 成功，所有核心 Playwright E2E 通过。
- 输出核心页面移动端和桌面截图，检查视觉一致性；无横向滚动和重大控制台错误。
- 至少一份 `docs/ACCEPTANCE_REPORT.md`：按 S0–S5 列出 PASS/FAIL/BLOCKED，每项附可复现命令和证据路径。
- `README.md` 能让全新机器按照说明本地启动 demo；`docs/privacy.md` 说明数据传输/可见性；`docs/backup-and-restore.md` 说明备份真实性与局限。
- 代码中没有任何硬编码密钥、真实私人资料；Git 历史无意外提交敏感文件。
- 如果用户没有明确授权部署，公开服务状态写 `NOT_DEPLOYED_BY_DESIGN`，不能以没有公网链接判开发失败；不可伪造上线记录。

## 最终总体验收定义（Definition of Done）

- [ ] 代码可从干净检出安装并启动，关键页面可操作
- [ ] 双人邀请、权限、回忆 CRUD 与私有媒体在真实后端经过正/负例测试
- [ ] 星空与时间线与同一数据源连接；纪念日、时间胶囊有效
- [ ] 离线 ZIP 能脱机直接打开、全部导出内容有完整性校验
- [ ] AI 检索给来源，无事实时不编造，不泄漏私有记忆
- [ ] 测试、构建、核心 E2E 通过，截图和最终验收报告齐全
- [ ] 任何没有服务账号或人工验收的项目均标记 BLOCKED，而不是虚假 PASS

只有勾选项经可核对证据达成，才可以宣称全局 GOAL 达成；若存在 BLOCKED_EXTERNAL，应以“本地版本已完成，线上能力待账号/授权”结项。
