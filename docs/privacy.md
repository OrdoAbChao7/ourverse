# OURVERSE 隐私与数据说明

OURVERSE 是私人产品，不是社交产品。本文说明数据存在哪里、谁能看到、什么时候会离开设备，以及哪些风险必须由使用者自己承担。

## 1. 基本原则

1. **默认保密**：私密记录只有作者可见；共同记录只有当前空间的两名成员可见；匿名与非成员看不到任何内容。
2. **最少外发**：演示模式不发起网络请求；真实模式只请求你配置的 Supabase 项目。
3. **明确告知**：DEMO 徽标、AI 开关说明、导出说明都直接写在界面里，不用含糊措辞掩盖真实行为。
4. **不做不可逆删除**：记忆使用软删除；真实数据库不提供客户端硬删除路径。
5. **密钥不进入前端**：浏览器只有 anon key；service_role key 与服务端模型密钥只在运维环境中。

## 2. 数据清单

| 数据 | 演示模式 | 真实 Supabase 模式 |
| --- | --- | --- |
| 账号身份 | 3 个内置虚构身份，无密码 | Supabase Auth 账号（邮箱 + 密码） |
| 会话 | `sessionStorage`，按标签页 | `supabase-js` 持久会话（默认 `localStorage`） |
| 记忆正文、标题、标签、地点、日期 | IndexedDB 数据库 `ourverse-local` | Postgres `public.memories` |
| 附件原始字节 | IndexedDB `attachments.data`（ArrayBuffer） | 私有 Storage bucket `memories` |
| 纪念日、胶囊元数据、胶囊正文 | IndexedDB | Postgres 表 |
| 邀请 | 本地哈希与状态 | 数据库只存 SHA-256 哈希 |
| AI 偏好 | IndexedDB，按用户 | `user_ai_preferences`，按用户、默认关闭 |
| 活动记录 | IndexedDB | `activity_logs` |
| 导出包 | 用户主动下载到本机 | 同左 |

演示数据全部为虚构内容；仓库不含任何真人资料。

## 3. 可见性规则

- **私密**：只有作者能读取、编辑、删除、导出、检索到。
- **共同**：空间内两名成员都能读取；只有作者能编辑或删除。
- **附件**：完全继承所属记忆的可见性，没有独立放宽。
- **胶囊正文**：开启时间到达之前，**包括作者在内**任何人都不能读取；真实后端由数据库 `now()` 与 RLS 强制。
- **非成员 / 匿名**：无法枚举空间、记忆、附件、纪念日或胶囊。
- **成员移除**：真实后端移除成员后，其后续 RLS 查询立即返回零行，即使仍持有未过期的 JWT。

## 4. 网络行为

### 演示模式

- 不请求 Supabase、不请求模型、不请求字体/CDN/分析服务；
- 页面只加载同源静态资源；
- 数据不会离开浏览器。

### 真实模式

- 只请求 `VITE_SUPABASE_URL` 指向的项目：Auth、PostgREST/RPC、Storage 签名 URL；
- 开启 AI 后，检索到的**可见**来源会发送到你部署的 `ai-ask` 函数；函数再按配置发给模型提供商；
- 不包含：密码、会话令牌以外的凭证、其他成员的私密内容、已删除内容、胶囊未开启正文、AI 索引或上传签名密钥；
- 仓库没有接入分析、广告、崩溃上报或第三方字体。

### 本地开发

- 本地 Supabase 的邮件进入 Mailpit（`http://127.0.0.1:54324`），不会真的发信；
- 没有配置任何模型密钥，因此本地不会发生外部 AI 请求。

## 5. AI 的数据边界

- 默认**关闭**；关闭时完全是本地确定性检索。
- 开启是**每个用户独立**的偏好；对方的开关不会替你开启。
- 服务端在调用模型前会：
  1. 校验 JWT；
  2. 只接受 source id，重新通过 RLS 读取数据库内容；
  3. 丢弃不可见、已删除、跨空间或不存在的 id；
  4. 要求调用者的 AI 偏好为开启；
  5. 校验模型输出的引用，不合法则拒绝。
- 函数不记录请求正文或来源正文，不返回提供商原始响应，不写回记忆。
- 一旦你启用，发送给模型提供商的内容受该提供商的条款与保留策略约束；这是启用前必须理解的外部风险。

## 6. 删除与保留

- **软删除**：记忆在列表、详情、附件、检索、导出中立即不可见；真实数据库保留行与审计信息，避免误删不可恢复。
- **胶囊**：开启后不可修改；没有客户端硬删除路径。
- **邀请**：可撤销；已使用、已撤销、已过期都会明确拒绝。
- **成员移除**：创建者可以移除另一位成员；数据仍属于空间，不随成员移除而删除。
- **演示数据**：设置页可重置（清空并重新播种）。这只影响本机 IndexedDB。
- **真实云端**：删除整个账号、清理存储对象、保留期限属于运维动作，当前未自动化；需要用户/运营者在 Supabase 控制台执行，并遵守当地法律与双方约定。

> 不做「自动不可逆删除」是刻意的安全选择：误删私人记忆的代价远高于保留。若你需要彻底删除，请先导出备份，再由账号所有者执行并记录。

## 7. 导出包的隐私风险

- 导出 ZIP **默认不加密**；
- 任何拿到 ZIP 或解压目录的人都能读取全部内容；
- ZIP 不包含对方私密内容、未开启胶囊正文、已删除记忆、令牌或密钥；
- 不要上传到公开网盘、代码仓库、聊天群或公开链接；
- 如需加密备份，请在导出后使用你自己信任的加密工具处理；
- 长期保存至少保留两份独立副本，并定期用 `SHA256SUMS.txt` 抽查完整性。

## 8. 威胁模型

### 已覆盖

- 同一空间的另一位成员读取作者的私密内容（本地与 RLS 双侧验证）；
- 非成员通过 URL、列表、搜索、AI、导出、胶囊读取内容；
- 通过伪造附件路径读取其他空间或其他记忆的文件；
- 通过修改系统时间提前打开演示胶囊（会话内单调时钟）；
- 通过客户端修改真实胶囊开启时间（数据库触发器 + RLS）；
- 通过旧签名 URL 在软删除后继续读取附件（每次复用前重新鉴权）；
- 通过重命名可执行文件或伪造 MIME 上传脚本（扩展名/MIME/魔数三重校验）。

### 不覆盖 / 非目标

- **设备被完全控制**：恶意软件、键盘记录、浏览器扩展可以读取屏幕上的一切；本产品不做端到端加密。
- **服务端运营者**：Supabase 项目管理员在数据库层面可以看到明文数据；这是托管后端的固有限制。
- **账号被盗**：密码泄露或邮箱被接管不在应用层防御范围内；请使用强密码与账号级二步验证。
- **恶意模型提供商**：启用 AI 后，发送内容受提供商策略约束。
- **法律强制披露**：托管服务商可能依法提供数据。
- **导出文件扩散**：一旦导出，应用无法追踪或撤回。

## 9. 上线前隐私检查清单（运维）

- [ ] 只使用私有 bucket，确认 `memories` 未设为 public。
- [ ] 确认前端环境变量只有 URL 与 anon key，没有 service_role key。
- [ ] 设置精确的 Site URL 与重定向白名单。
- [ ] 根据双方约定决定是否强制邮箱验证。
- [ ] 确认 `AI_ALLOWED_ORIGIN` 是唯一生产 Origin，且未配置 `*`。
- [ ] 模型密钥只存在 Edge Function secrets，确认未写入仓库、日志或 `.env`。
- [ ] 配置数据库备份/PITR，并完成一次恢复演练。
- [ ] 阅读并接受 Supabase 与模型提供商的数据处理条款。
- [ ] 告知另一位使用者：数据存在哪里、AI 开启会发生什么、导出包不加密。

## 10. 事件响应（建议）

1. 立即在 Supabase 撤销泄露的密钥/会话，必要时轮换 anon key 与模型密钥。
2. 将 bucket 设为私有并检查 Storage 访问日志。
3. 撤销所有邀请，移除可疑成员。
4. 从备份恢复前先隔离受损环境，保留必要审计记录。
5. 如果导出包泄露，视为不可撤回：通知另一位使用者，轮换相关凭证，停止继续分发。
